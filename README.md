# 北宇治润色工坊 Version 2

当前翻译认知能力、明确边界与后续强类型世界模型方案见 [TRANSLATION_COGNITION_AUDIT.md](./TRANSLATION_COGNITION_AUDIT.md)。

Version 2 是面向长篇日文小说的 Windows 桌面翻译、润色、复核与 EPUB 成品工具。它不是把整本书一次性塞给一个模型，也不把术语表当成唯一长期记忆：软件负责持久保存原书结构、章节摘要、人物与实体证据、关系变化、称呼轨迹、事件、知识边界、译文版本和人工裁定，再按当前段落检索并组装给不同 AI 工位。

当前正式便携版：`v0.0.5`。主目录仅为本 `Version2` 文件夹；源码历史只使用 Git 与 GitHub tag 管理，不再建立本地序号备份。

## 正式工作流

1. 从系统文件窗口导入日文或日中双语 `.epub`，也可导入日文 `.txt`。
2. 全书预读按章节顺序建立术语、人物、关系、称呼、事件、声音、场景、伏笔、秘密、谐音与双关证据，并为每项绑定章节、分段、读者揭示点、角色知识点和叙事世界线。
3. 软件以当前段、原译文、近邻、已确认术语、当前场景/叙事层、分段级世界状态、关系阶段、段内变化证据和读者/角色知识边界组装翻译上下文。
4. 主模型生成候选后，依次经过确定性硬规则、限次自我修复和独立模型复核。格式灾难会拆批隔离；失败稿不能成为成稿。
5. 只有身份隐藏、文学多解、谐音双关、用户锁定冲突或模型反复分歧等无法自动裁定的情况进入人工复核。
6. 工作台支持原文、既有中文和当前成稿并列、人工编辑、版本历史与恢复；阅读页支持原文/译文/对照模式和阅读排版设置。
7. 全部段落通过且复核队列清空后，生成 JP→SC、SC→JP 或纯中文 EPUB。人工批准的必要注释会以 EPUB 3 弹注并带章末回链写入。

## 忠实边界

- 日文原文是译文内容边界：不得增译、漏译、擅自补动作、因果或心理。
- 原文没有性别词、代词、人数或称呼时不得添加，即使长期人物资料已经确认；中文自然时优先省略主语。
- 原文明示的数字、否定、程度、单复数、称呼、口吃、重复、语气和有表达作用的形式不得删减。
- 粗俗、激烈、露骨、冒犯或禁忌表达不得净化、弱化、美化、回避或“善意改写”，也不得反向加码。
- 称呼并非全书固定字符串。它由当前原文形式、说话人→对象的关系阶段、场景正式度和意图决定；原文没有时不能自行添加“小、君、酱、先生、小姐”。
- 标准专名保持稳定；戏称、误读、昵称、谐音和双关作为有证据、有场景范围的变体处理。
- 译者可用后文真相消歧，但译文不能提前剧透，也不能让角色知道当时不可能知道的事。

内置规则见 [electron/workflow/prompts.cts](./electron/workflow/prompts.cts)，程序质量门见 [electron/workflow/translationValidation.cts](./electron/workflow/translationValidation.cts)。

## 模型接口

“设置 → 模型与接口”内置以下配置：

- DeepSeek 官方：默认 `https://api.deepseek.com`，默认模型 `deepseek-v4-flash`；
- Kouri API：默认 `https://api.kourichat.com/v1`，只填域名时也会自动补 `/v1`；
- Command Code GOAT：默认 `https://api.commandcode.ai/provider/v1`，使用 Studio 创建的同一 API Key；Claude 自动走 Anthropic Messages，OpenAI、Gemini 与开源模型自动走 Chat Completions；
- 其他 OpenAI-compatible 服务：自定义 HTTPS Base URL、协议与模型名。

Chat Completions、Responses 与 Anthropic Messages 使用各自端点、请求体和返回解析，不会混用。可分别设置翻译模型、全书预读模型、独立复核模型与知识/审校 Agent 模型，并配置批量、并发、超时、最大重试、输出 Token、温度与推理强度。Kouri 会按模型实测 Responses `reasoning.effort`，成功后记录有效档位，失败则逐级降档并最终回退默认推理。Command Code 不发送 `thinking`、`reasoning_effort` 或 `reasoning`，其 DeepSeek、Claude、Gemini、GPT 与其他模型均采用聚合服务和上游默认推理；Claude 自动使用 Anthropic Messages，其他模型使用 Chat Completions。Command Code DeepSeek 的 JSON 任务先发送原生 `response_format=json_object`，被具体上游拒绝时自动降为严格提示与本地校验，并在本次运行中记住；内置 GOAT 配置的最大输出为 18432 Token。可选 ZDR 会发送 `x-cmd-zdr: 1`，没有 ZDR 上游时明确提示关闭或换模型。连接测试会产生极小的真实模型调用；模型列表以服务端实际返回为准。

运行终端会为每次预读、翻译、A→B 语义角色分析和复核请求显示服务、模型、协议、思考请求、JSON 处理方式、实际输出上限、超时与原文字数。等待超过 30 秒时持续输出心跳；限流、网关错误、协议/参数降级和重试都会显示原因。明确的输出长度截断不会原样重试，而是立即进入拆分；预读还会记住并持久保存本次学到的安全分片长度，后续分片预先拆开。当前版本可继续拆到约 240 字，并对截断、无效 JSON、空响应、网关/网络/超时以及整章覆盖修复失败执行有上限的章节级断点恢复。

API Key 通过 Electron `safeStorage` 使用当前 Windows 用户的系统加密能力保存；完整密钥不返回界面，也不写入项目数据库、普通设置、操作日志、缓存、备份或 EPUB。

## EPUB 与数据安全

- 导入前验证 ZIP 路径、重复项、加密项、压缩比、解压上限、container、OPF、spine、NAV/NCX 和 XHTML。
- 书内 XHTML 只做非执行型解析；script、事件属性和外链不会在软件中运行。
- 原始 EPUB/TXT 字节与 SHA-256 保存为不可变快照；项目事实、任务、术语、字符级时态实体/别名/声明/事件/角色知识、嵌套叙事层、分层记忆、歧义、系列记忆、复核、译文依赖和版本进入 SQLite v9。
- 翻译前对当前段落建立 agent/patient/recipient 与 speaker/addressee 语义角色账本；翻译与独立复核都必须检查主动、被动、使役、授受表达以及谁对谁说话。
- 同章状态、关系、称呼、知识或场景发生变化时，翻译批次会在分段边界处自动拆分；同一段内再按 UTF-16 字符位置切成精确材料片，变化前后不会共用一个状态。
- human-reading-v4 要求人物、别名、术语与事实/事件/场景中的引用键互相对应。旧提示版本的暂停预读继续后会自动重新核对已处理章节，避免“事实里认识主角、术语表却为零”的残缺结果进入翻译。
- Command Code 不发送 `thinking`、`reasoning_effort` 或 `reasoning`，也不执行 Command 专属思考探测与降档；由聚合服务和上游模型自行采用默认推理模式。DeepSeek 官方与 Kouri 仍保留各自设置。
- 暂停会中止在途请求并阻止可选复核继续启动新请求；人物/术语引用覆盖在全部分片读完后按整章统一检查。`敵、兵士`等未命名泛称只保留在事实叙述中，不会进入术语表。
- 预读具有有上限的章节级自动恢复；失败章节的术语、事实和事件留在分片断点中，任务中心和工作台提供“从断点重试失败章节”。章节只在整章校验通过后原子写入正式知识表。
- v0.0.3 修复界面重写回归：Agent 面板恢复不透明可读；沉浸阅读不再用原文冒充译文；空项目与未定稿项目不能导出；模型设置恢复密钥尾号、协议、模型列表、重试与输出上限；缓存/数据库迁移入口恢复；新增带双重确认的全数据初始化。
- v0.0.4 修复跨段引语被模型擅自补齐的问题：逐段校验引号/括号的字符、方向与数量；安全撤销新增的段首/段尾配对符号；旧成稿升级后自动生成可追溯的自修复版本。
- v0.0.5 修复双语工作台将“原译/机翻参考”冒充为“润色成稿”的显示回填，并阻止查找替换把尚未润色的参考译文意外保存为正式版本。
- 场景与章节结束后会巩固记忆；新状态通过 supersedes 链替代旧状态，旧证据不删除。普通细节自动降权/归档，人物、关系、设定和关键事件按规则长期保留。
- 跨卷记忆必须由用户在“记忆 → 跨卷系列记忆”中明确指定系列和卷序，只继承较早卷中已确认/锁定且无冲突的实体、术语、文风和长期记忆。
- 译文版本记录实际使用的实体、声明、事件和原文证据；后续知识或规范译名变化会把受影响成稿安全转为需复核，而不覆盖旧版本。
- 应用异常退出时，在途任务恢复为可继续状态；大章预读每完成一个分片就保存断点，暂停、继续、取消会传播到实际网络请求。
- 正式导出从原书快照重建，保留封面、插图、CSS、ruby、链接、脚注、锚点、阅读顺序和其他未修改资源，并重新解析输出结构。
- 正式导出不会接受失败、未复核或无选中成稿的段落。覆盖目标时先写完整临时文件，再替换。
- 删除书架项目不会删除磁盘上的原 EPUB/TXT；清空派生缓存不会删除项目、术语、草稿或阅读位置。
- “设置 → 文件与缓存 → 项目数据库”可把活动数据库迁移到 D 盘等自定义目录。迁移在重启时进行，核对完整性、schema 版本和项目数量后才切换；失败继续使用原库，目标已有同名数据库时拒绝覆盖。

## 运行与构建

正式便携版位于 `release/北宇治润色工坊V2-win-x64`，双击 `北宇治润色工坊V2.exe`。必须保持目录内容完整。

开发目录常用命令：

```text
npm test
npm run build
npm run package
```

构建脚本会执行类型检查和生产构建，再生成 Windows x64 便携目录。正式使用步骤和边界见便携包内的 `使用说明.txt`。

## 现实质量边界

这套架构解决的是普通短上下文方案最缺乏的持续认知、证据、阶段性关系、版本和复核问题，并把人工审核压缩到无法可靠自动裁定的少数场合。它能显著接近“带着全书理解翻译”的工作方式，但不能诚实地承诺任意模型、任意小说都自动达到优秀人类译者水平。真正达到该目标还需要用专业日中译者稿件做盲评，并对严重增译、漏译、净化、人物误判和意义反转实行一票否决。

功能完成状态与发布核对以 [TODOLIST.md](./TODOLIST.md) 为准。详细设计仍保存在 `PROJECT_BRIEF.md`、`ARCHITECTURE.md`、`CONTEXT_AND_TRANSLATION_PIPELINE.md`、`LONG_RANGE_MEMORY_DESIGN.md`、`REVIEW_AND_ADJUDICATION_DESIGN.md` 和 `EPUB_PROCESSING_DESIGN.md`。
