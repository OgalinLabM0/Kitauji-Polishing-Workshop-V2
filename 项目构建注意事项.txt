一、 【版本管理与 GitHub 提交闭环（唯一真实来源）】
本地历史离散序号备份已全部作废，本项目统一采用 Git + GitHub 远程仓库进行标准化版本演进，基准初始版本为 v0.0.0。
每次修改代码、解决 Bug 或增加新功能，在确认自测通过（`npm test` 100% PASS 且 `npm run build` 0 错误）后，必须严格执行以下三步闭环：

1. 【版本号同步】：
   - 根据改动性质适度递增 `package.json` 与 `packaging/app-package.json` 中的版本号（如 `0.0.1`、`0.0.2`……）；
   - 同步更新系统内的构建产物与说明。

2. 【Git 规范提交（附详尽版本差别说明）】：
   - 执行 `git add .` 将全部改动文件纳入暂存区；
   - 执行 `git commit -m "..."`，Commit Message 必须包含结构化详细说明：
     * 提交标题：`feat/fix/refactor(模块名): 简明扼要概述 [vX.Y.Z]`
     * 改动动因：为什么做本次改动、解决了什么具体问题；
     * 版本差异：相对上一版本的具体代码与行为变化（改动前效果 vs 改动后效果）；
     * 影响范围：涉及的核心模块与文件清单；
     * 验证结果：测试用例（如 171 项全通）与构建状态。

3. 【GitHub 远端实时推送 (Mandatory)】：
   - 每次 commit 后必须立即执行 `git push origin master`（或 `main`）同步至用户 GitHub 仓库（https://github.com/OgalinLabM0）；
   - 若有重大 milestone，打上对应的 git tag（如 `git tag -a v0.0.1 -m "Release v0.0.1"`）并推送 tag。

二、 【代码架构与质量契约】
1. 严禁单文件代码堆叠：所有功能必须严格解耦，拆分为领域模型、工作流服务、存储层、UI 组件与测试用例，禁止将上千行杂乱逻辑塞入单个文件。
2. 忠实度与文学质量铁律：严禁增译、漏译、擅自脑补，严禁将粗俗/露骨内容委婉化/净化，标点符号（『』、「」、【】、——、……）必须 100% 等值保留。
3. 数据库与物理几何安全：所有区间偏移量、时态世界状态、称呼别名必须严格遵守物理自愈与外键完整性约束。
