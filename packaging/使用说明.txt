北宇治润色工坊 Version 2 · v0.0.5 正式便携版

启动
1. 保持本目录内所有文件和文件夹原样，不要只复制 exe。
2. 双击“北宇治润色工坊V2.exe”。
3. 在起始页进入书架，导入日文或日中双语 EPUB/TXT。

首次配置模型
1. 打开“设置 → 模型与接口”。
2. 可直接选择“DeepSeek 官方”“Kouri API”或“Command Code GOAT”，也可新建通用 OpenAI-compatible 配置。
3. 填写 API Key；Kouri 官方地址可填 https://api.kourichat.com 或 https://api.kourichat.com/v1。Command Code 使用 Studio 创建的同一 API Key，官方地址已预填为 https://api.commandcode.ai/provider/v1。
4. Kouri 不同模型可能分别使用 Chat Completions 或 Responses。连接测试会自动尝试两种协议并把成功的一种保存到配置；Responses 模型还会实测所选 reasoning 档位，失败时自动降档或回退默认推理。
5. Command Code 会按每次请求的实际模型自动分流：Claude 使用 Anthropic Messages，其他模型使用 OpenAI Chat Completions。软件不会向 Command Code 的任何模型发送 thinking、reasoning_effort 或 reasoning，也不进行思考能力探测和降档；推理由聚合服务和上游模型默认决定。GOAT 请求会消耗套餐额度并受套餐模型范围限制；可选 ZDR 可能改变上游和费用，模型无 ZDR 上游时会明确失败，默认关闭。
6. 分别填写主模型、全书预读模型、独立复核模型和 AI 知识/审校 Agent 模型。DeepSeek/Kouri 默认模型为 deepseek-v4-flash；Command Code 默认模型为 deepseek/deepseek-v4-flash，思考设置固定为上游默认。第三方服务请以实时模型列表中的准确名称为准。
7. 保存并启用后运行连接测试。连接测试会发送一次极小的真实请求，服务商可能计费。
8. 内置 Command Code GOAT 配置使用 18432 Token 输出上限。DeepSeek JSON 任务优先使用原生 JSON 约束；网关不支持时会自动降级并在运行终端说明。旧版内置 8192 配置会自动升级，DeepSeek 官方、Kouri 和用户自建配置不会被擅自修改。
9. 设置页会显示密钥是否已经保存及末四位提示，不会显示完整密钥；“最大输出 Token”是必填请求上限，保留默认值即可。提高它只会降低超长结构化响应被截断的概率，不会自动提高翻译质量。

推荐工作顺序
1. 导入作品并核对内容类型、章节与正文结构。
2. 在“润色 / 翻译”先运行“全书预读”。软件会分章建立术语、人物、关系、事件、称呼变化、文风、场景、秘密、双关、嵌套叙事和字符位置证据；每章结束自动巩固记忆，旧状态保留为历史而不覆盖。
3. 在“术语与专名”检查低置信度或冲突条目；在“记忆”检查分层事实和歧义工作台。跨卷作品只有在你明确填写相同系列名和正确卷序后，才会继承更早卷的已确认记忆。
4. 运行翻译。纯日文项目生成中文；日中双语项目以日文为事实边界润色既有中文。每批会得到 agent/patient/recipient、speaker/addressee、本地句法证据、文风决策和歧义策略；同段变化按 UTF-16 offset 切片，后半段状态不会倒灌前半段。知识更新后受影响译文会转入复核而不覆盖旧版本。
5. human-reading-v4 增加人物实体覆盖硬校验。继续由旧提示版本暂停的预读任务时，软件会自动重新核对已处理章节，补齐人物、别名、术语及 A→B 引用绑定；旧任务与累计 Token 记录不会丢失。
6. Command Code 已完全移除显式 thinking/reasoning 参数、思考能力探测与自动降档；其中所有模型均使用上游默认模式。DeepSeek 官方与 Kouri 的思考设置不受影响。
7. 软件在每章全部分片读完后才统一检查人物/术语引用。前面分片可由后续分片和前章已建立实体补足；“敵、兵士”等未命名泛称只保留在事实叙述中，不会进入术语表。
8. 预读会对截断、空响应、无效 JSON、网络/网关/超时及整章实体修复失败执行有上限的章节级断点恢复。若最终仍失败，任务区会显示“从断点重试失败章节”；已完成分片中的术语、事实和事件不会清空。
9. 运行独立复核，在“复核队列”只处理无法自动裁定的项目。
10. 在工作台抽查或修改成稿；每次修改都会保留版本，可以恢复。
11. 所有段落通过且复核队列清空后，在“导出与版本”生成日中、中文在前或纯中文 EPUB。
12. 0 段、未 100% 定稿或仍有未决复核时，正式导出按钮与后端都会阻止导出，不会先弹出保存窗口。

暂停、关闭与继续
- 全书预读按章保存正式结果，并在大章内每完成一个分片就保存断点。
- 点击暂停会立即阻止任何新模型请求，并取消当前在途请求；若暂停发生在分片复核阶段，该取消不会再被当成普通复核失败吞掉。
- 正常关闭或异常退出后，再次打开作品主页或“润色 / 翻译工坊”，点击“从断点继续”即可续跑原任务。
- 已完成章节、术语与记忆不会因关闭软件而清空；不要另建翻译任务来代替未完成的预读任务。
- 全书预读完成后还会保存卷级档案；关闭软件后仍由 SQLite 持久化，继续任务不会从零开始。
- 运行终端每 30 秒报告仍在等待，并显示服务、模型、协议、思考、JSON 方式、输出上限、超时、重试和原文字数。模型明确返回长度截断时不会原样盲重试；预读会拆分并记住安全长度，关闭后也能从该策略断点继续。
- 出现 WARN 不一定代表内容丢失：可选独立复核失败时会保留已成功的初次提取；可恢复的章节错误会明确显示自动尝试次数。章节通过整体验证前，已提取术语/事件只保存在章节断点而不提前进入正式表，以免半章知识污染后续翻译。

忠实原则
- 日文没有的信息不得添加，日文明示的信息不得删减；特别包括性别、人数、称呼、数字、否定、程度、口吃和重复。
- 原作的粗俗、激烈、露骨、冒犯或禁忌表达不得净化、弱化、美化、回避，也不得反向加码。
- 称呼由当前原文、人物关系阶段、场景与意图共同决定，不做机械全书统一；原文没有称呼时不得擅自补“小、君、酱、先生、小姐”等。
- 已知性别和人数只用于理解，不能授权模型向当前句添加原文不存在的代词或复数。

数据与安全
- API Key 使用 Windows 提供的加密能力保存，不写入作品数据库、普通设置、日志或导出文件。
- 导入时保存不可变原文件快照。删除书架项目不会删除磁盘上的原 EPUB/TXT；清理缓存也不会删除项目、草稿、术语和阅读进度。
- EPUB 在非执行环境中解析；书内脚本、事件属性和外链不会运行。
- 正式导出只接受通过硬规则和复核的成稿；未完成段落或未裁定复核会阻止导出。
- 沉浸式阅读的译文、日文、双语和原译模式严格按所选材料显示；缺少译文时明确标注，不会把日文原文伪装成中文译文。
- “设置 → 文件与缓存 → 清空所有数据并初始化软件”需要输入“初始化”并再次确认。它会在重启时删除软件内项目、译文、记忆、任务、密钥、偏好、缓存、日志和自动安全备份，但不会删除你自行导出的成书、手动数据库备份或磁盘原书。
- 覆盖同名输出时，软件先生成完整临时文件，再替换目标，避免留下半个 EPUB。
- 软件在 SQLite schema 升级前自动建立快照；“设置 → 文件与缓存 → 项目数据库”可导出和恢复包含任务断点在内的整库备份。恢复前还会自动保留当前库的安全副本。整库备份不包含 API Key。

整库备份与恢复
1. 打开“设置 → 文件与缓存”，在“项目数据库”选择“导出整库备份”。软件会检查 SQLite 完整性、schema 版本和项目数量后再保存。
2. 恢复时选择“从备份恢复”。软件先把所选文件复制到应用暂存区并校验，不会立即覆盖当前库。
3. 点击“立即重启并恢复”。启动阶段先为当前库建立 pre-restore 安全副本，再安装并复验所选备份。
4. 备份版本高于当前软件支持版本、缺少项目表或完整性不通过时会拒绝恢复。

把项目数据库迁移到 D 盘
1. 打开“设置 → 文件与缓存”，向下找到“项目数据库”。
2. 点击“选择位置”，选择 D 盘中的固定目录，例如 D:\北宇治润色工坊数据。
3. 点击“立即重启并迁移”。软件会在重启时复制当前完整数据库，并核对完整性、schema 版本和项目数量。
4. 只有所有检查一致才会切换到 D 盘并移除原数据库文件；失败时仍使用原位置，界面会显示原因。
5. 目标目录如果已有 kitauji-v2.sqlite，软件不会覆盖。需要使用空目录或先自行确认已有文件用途。
6. 以后不要手工移动或改名该数据库；要迁回系统默认位置，请使用同一页面的“迁回系统默认”。
说明：实际项目数据库可以完全位于 D 盘；用于记住其位置的极小设置文件仍由 Windows 放在当前用户配置目录。

显示
- “设置 → 显示与排版”可调整主内容字号；也可使用 Ctrl+加号、Ctrl+减号、Ctrl+0。
- 最左侧主导航保持稳定尺度，其余正文、表单和操作区使用更大的可读字号。
- 窗口可自由调整；小窗口会改为上下布局，长书名和路径完整换行。

重要边界
- 模型质量仍取决于所选模型、服务稳定性和原书难度。软件通过长程证据、独立复核、硬规则和最小人工队列降低错误，但不会宣称任何模型在所有文学作品上自动等同优秀人类译者。
- 高难度双关、身份隐藏、原文歧义以及模型反复分歧仍可能必须人工裁定；界面会同时给出日文、译文和上下文证据。
- 建议先做连接测试，再完成全书预读；正式翻译时可先只选一章核对质量和参数，确认后再继续整本。
